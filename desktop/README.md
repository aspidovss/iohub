# iohub-desktop — внутренняя документация по сборке

Хост на Rust + Tauri 2, который раздаёт встроенную копию интерфейса web.io.vision и
даёт ему доступ к клавиатуре через собственный мост WebHID (hidapi). Интернет для
работы не нужен. Дамп интерфейса лежит в `../vendor/io-web`, собирается в
`../webview`. Сам дамп не изменяется руками: правки возможны только в хосте, в шиме
`../webview/webhid-shim.js` и в сборщике `prepare_webview.py`.

Публичное описание — в `../README.md`, здесь только заметки для сборки.

## Что готово (26.11.2026, версия 0.8.5.1.2 — интерфейс 0.8.5.1)

* Офлайн-запуск: интерфейс целиком внутри программы, сетевых запросов при обычном
  прогоне 0 (проверено записью каждого обращения страницы наружу).
* Клавиатура IO Type 68 Pro ICE (VID 05ac, PID 024f) подключается по служебному
  каналу usagePage 0xFF68 / usage 0x0061, интерфейс MI_02, отчёты по 64 байта.
* Настройка раскладки работает и сохраняется в памяти клавиатуры: клавиша Print →
  Pause пережила перезапуск программы, затем возвращена к Print (тоже пережило).
* Права доступа хранятся по паре VID:PID (`hid-allow.json`), перетыкание кабеля в
  другой порт их не сбрасывает.
* Два способа установки: NSIS-установщик и портативный EXE. Оба проверены.
* Кнопка «Старый софт» убрана правкой ссылок, вывод окна и название программы —
  нейтральные (`iohub-desktop`), значок нарисован свой. Знак бренда в шапке интерфейса
  тоже убран правкой (`logo:`` в конфиге бренда): пустой знак — штатный путь интерфейса,
  он рисует на его месте название текста.
* «Сообщить об ошибке» — своя панель: описание + собранный журнал, письмо на
  iohub@aspidov.ru, задача на GitHub, сохранение в `reports\`. Имя пользователя из
  путей вырезается, серийник сокращается. У отчёта есть номер `HUB-ГГГГММДД-XXXXXXXX`
  (как у веб-версии, но с нашим префиксом): он выдаётся при каждом открытии панели,
  попадает в шапку отчёта, в тему письма и в заголовок задачи, а имя файла отчёта
  кончается теми же восемью символами. К отчёту шим добавляет последние 60 нажатий
  кнопок и ссылок страницы (только подписи, без введённого текста) и поля со страницы:
  версия интерфейса, язык, экран, счётчики устройств.
* Версию самого интерфейса он нигде не показывает, и она не лежит в имени файла
  модуля. `prepare_webview.py` достаёт её из главного модуля дампа и кладёт в
  `<meta name="iohub-ui-version">`; оттуда её читают шим, строка внизу настроек и
  отчёт о проблеме.
* Внизу экрана настроек шим дописывает строку о программе: оболочка и её версия,
  версия интерфейса, ссылки «страница проекта» и «сообщить об ошибке». Экран настроек
  узнаётся по заголовку «Настройки хаба», строка переживает перерисовки и смену языка.
* В шапке интерфейса две кнопки добавляет шим: «Справка» (краткая памятка, `help.html`
  из `../docs/app-help.html`, язык — тот же, что выбран в интерфейсе) и «GitHub»
  (страница проекта через системный браузер). Ссылки разрешены белым списком в
  `open_link`: почта поддержки, адрес проекта и `*.io.vision`.

## Как собрать

```powershell
# 1. Обновить вебview из дампа интерфейса (обязательно после правок в ../vendor/io-web или ../webview)
python desktop\prepare_webview.py

# 2. Быстрая проверка
cargo build --offline --manifest-path desktop\Cargo.toml

# 3. Релиз и установщик (из каталога desktop)
cd desktop
$env:CARGO_NET_OFFLINE = "true"
cargo tauri build          # NSIS уже в %LOCALAPPDATA%\tauri\NSIS
```

Перед сборкой закрывать запущенную программу, иначе линковщик не может перезаписать
`target\release\iohub-desktop.exe`: `Get-Process iohub-desktop | Stop-Process -Force`.

Готовые файлы после сборки лежат в `desktop\target\release\bundle\nsis\` и рядом в
`target\release\iohub-desktop.exe`; в `desktop\dist\` складываются копии для раздачи:
`iohub-desktop.exe`, `iohub-desktop_<версия>_x64-setup.exe`,
`iohub-desktop-<версия>-portable.zip`, `README.txt`.

## Чем помогать себе при сборке

| Файл | Зачем |
| --- | --- |
| `tools/fetch-site.ps1` | собирает `vendor/io-web` из целиком сохранённой страницы web.io.vision: чистит шапку, пересобирает тело, обходит весь JS/CSS и докачивает недостающее; требует интернета, подробности в `../README.md` |
| `tools/find_firmware_urls.py` | ищет в собранном `../webview/assets` адреса и точки настройки ссылок — им проверяли, куда переехал адрес списка прошивок |
| `tools/check_report.py` | смотрит сохранённые отчёты в `%APPDATA%\...\reports`: имя файла и не осталось ли в тексте имени пользователя |
| `tools/check_icons.py` | быстрая проверка значков программы: размеры, прозрачные углы, узнаваемость рисунка |
| `prepare_webview.py` | собирает `../webview` из дампа: шим, правки ссылок, подпись окна, `help.html`, зонд `probe.html` |

`prepare_webview.py` внедряет правки по имени главного модуля (`index-D17H6_-L.js`) и
по подключению ES-модуля в `index.html`. После обновления дампа эти места меняются —
сборщик тогда не молчит, а останавливается с внятной ошибкой.

## Файлы программы во время работы

Папка `%APPDATA%\vision.io.hub.desktop\`:

| Файл | Назначение |
| --- | --- |
| `iohub-desktop.log` | журнал работы (короткий обычно, подробный с `debug.on`) |
| `hid-allow.json` | пары VID:PID, которым разрешён доступ |
| `firmware.url` | одна строка https-адреса со `{vid}`, `{pid}`, `{product}` — включает список прошивок |
| `debug.on` | пустой файл: подробный журнал, снимки экранов, записи наружу |
| `autotask.txt` | сценарий проверки интерфейса (только с `debug.on`) |

## Политика доступа к сети

`tauri.conf.json` разрешает запросы наружу только на `https://*.io.vision` — этого
достаточно, чтобы работать со списком прошивок, если производитель укажет адрес.
Проверено: адрес производителя проходит, чужой адрес блокируется политикой
(в журнале появляется строка «запрещено политикой … (connect-src)»). Остальная
работа офлайн не меняется.

Прошивки: свой адрес списка веб-версия не имеет — в конфигурации бренда на живом
сайте есть только `old.io.vision` и `vk.com`, а прямые обращения к
`web.io.vision/api/firmware*` дают 404. Поэтому адрес берётся из `firmware.url`.
Без файла вкладка Maintenance работает как в веб-версии: установленная версия,
установка из файла `.hex`. Правка `prepare_webview.py` лишь заменяет отсутствующую
ссылку на переменную `window.__iohubFirmwareLink`, сам интерфейс не переделан.

## Что осталось: сборка под Linux

На этой машине нет ни WSL, ни Docker, поэтому список собран по коду и по сборке в
автосборке GitHub: там Linux доходит до компиляции и падает там, где не хватает
пакетов. Запуск на реальном железе по-прежнему не проверен.

1. Пакеты для Tauri: `libwebkit2gtk-4.1-dev libgtk-3-dev libayatana-appindicator3-dev
   librsvg2-dev libssl-dev pkg-config`, плюс `libudev-dev` — на него опирается сборка
   crate `hidapi` 2.6.7 даже с фичей по умолчанию `linux-static-hidraw` (проверено в
   автосборке: без `libudev-dev` сборка падает со словами «Unable to find libudev»).
   `libusb-1.0-0-dev` понадобится только при переходе на бэкенд
   `linux-native-dyn-libusb`. Внутри webview менять ничего не нужно: шим — обычный
   JavaScript, Wry под Linux использует WebKitGTK.
2. Выбор служебного интерфейса. На Windows каждый интерфейс USB — отдельное
   устройство с путём `...&MI_02#...`, и hidapi заполняет `usage_page`/`usage`, чем
   и пользуется фильтр интерфейса (0xFF68/0x0061). На Linux у hidraw-бэкенда эти поля
   равны нулю, а путь выглядит как `/dev/hidrawN`: в `src/hid.rs` нужно определять
   канал по разбору отчётного дескриптора (`HIDIOCGRDESC`) либо по номеру интерфейса
   из libusb-пути и размерам отчётов (64/64/64). Пока это самое место, где Linux
   разойдётся с Windows.
3. Права на устройство — сделано с 0.8.5.1.2: `desktop/linux/udev/99-iohub-desktop.rules`
   ставится из `.deb` в `/etc/udev/rules.d/` и перечитывается postinst-скриптом; тот же
   файл выходит в релиз отдельно — он нужен тем, кто берёт AppImage. Правила на
   `TAG+="uaccess"` (доступ активной сессии входа), вендоры совпадают со списком
   `ALLOWED_VENDORS` в шиме. Разрешения по VID:PID в `hid-allow.json` остаются как есть.
4. Закрытие окна: сейчас для Windows сделан отдельный случай (`main.rs`,
   `#[cfg(target_os = "windows")]`) — проверить, что на Linux окно закрывается обычно.
5. Бандлинг — сделано: `deb` и `appimage`, `.desktop` и иконки Tauri делает сам (состав
   пакета проверен по файлу из автосборки: `usr/bin`, `.desktop`, четыре иконки, правило).
   В `bundle.linux.deb.depends` намеренно только `libudev1`: bundler добавляет свой список
   webkit/gtk сам, а если вписать их вручную, в `Depends` появляется дубль — так и вышло в
   первом пакете. Версия в метаданных пакета трёхчастная (`0.8.5`), даже когда файл
   называется `0.8.5.1.2`: Tauri принимает только три части, полная версия — в имени файла,
   в заголовке окна, внизу настроек и в справке.
6. Проверка записи в память возможна только на настоящем железе: клавиатуру нужно
   подключить к Linux-машине (в WSL без проброса USB не выйдет).
