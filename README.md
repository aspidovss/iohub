# iohub-desktop

Программа для настройки клавиатур **IO Red Square** без интернета: интерфейс конфигуратора
внутри приложения, доступ к клавиатуре идёт напрямую через USB, а не через браузер.

> Неофициальный проект, сделан для личного пользования и не связан с производителем.
> Название и значок не используют чужой товарный знак. Подробности — в конце,
> в разделе «Лицензия и происхождение интерфейса».

## Зачем это нужно

Веб-версия конфигуратора работает только открытой в браузере и только с сетью: без
интернета страница не грузится, а клавиатуру браузер видит лишь в Chrome и только
по WebHID. Здесь то же самое работает локально.

- Работает **без интернета**: ни одного обращения наружу во время работы (проверялось
  снимками сетевого журнала).
- Без аккаунта, без входа, без статистики.
- Краткая памятка и ссылка на проект — внутри программы: кнопки **«Справка»** и
  **«GitHub»** в шапке окна, на всех экранах.
- Внизу настроек — строка о программе: что это за оболочка, её версия, версия самого
  интерфейса и ссылки на проект и на отчёт об ошибке. Чужой знак бренда из шапки
  убран при сборке: остался только текст названия.
- Раскладка применяется к клавиатуре и остаётся после перезапуска компьютера и
  выдёргивания кабеля.
- Прошивка не трогается сама собой: по умолчанию вкладка «Обслуживание» просит файл
  `.hex`, и список прошивок появляется только если вы сами пропишете адрес.
- Клавиатура не открывается, пока вы не разрешите доступ, — разрешение хранится
  отдельно и его можно отозвать.

## Как устроено

```
интерфейс конфигуратора (встроен в программу)
        ↓  navigator.hid  (WebHID)
webview/webhid-shim.js   — восстанавливает WebHID, которого нет в WebView2
        ↓  команды Tauri
desktop/src/main.rs      — разрешения, журнал, отчёт о проблеме
        ↓
desktop/src/hid.rs       — поток HID, разбор отчётов
        ↓  hidapi
USB-клавиатура
```

Интерфейс не изменён: он запускается как есть, а недостающий браузерный API
подставляется снаружи. Правки четыре, все делаются сборщиком `prepare_webview.py` и
описаны прямо в нём: убрать ссылку «Старый софт», сделать адрес списка прошивок
настраиваемым, включить почту поддержки и поставить нейтральную подпись окна.

## Что поддерживается

В каталоге интерфейса 34 модели. Программа показывает устройства трёх вендоров:

| VID  | PID    | Что это                             |
|------|--------|-------------------------------------|
| 05AC | 024F   | IO Type 68 Pro ICE (проверено здесь) |
| 05AC | 0256   | другие клавиатуры той же серии      |
| 0C45 | FEFE   | старые модели (3141 / 65278)        |
| 3554 | F511   | мыши                                |

Список «какие устройства программа вправе открыть» лежит в файле `hid-allow.json`
(см. ниже) и заполняется сам при первом разрешении доступа.

## Установка — Windows

1. Скачайте из [Releases](../../releases) свежие `iohub-desktop_<версия>_x64-setup.exe`
   (установщик) или `iohub-desktop-<версия>-portable.zip` (портативная версия).
2. Установите или распакуйте в любую папку и запустите.
3. Подключите клавиатуру и при первом запросе нажмите «Разрешить».

Нужны Windows 10/11 64-bit и WebView2 Runtime (в Windows 11 он уже есть; в Windows 10
обычно приходит с обновлением или с установщиком).

## Linux

В [Releases](../../releases) лежат `iohub-desktop_<версия>_amd64.deb` и
`iohub-desktop-<версия>.AppImage` (сборка на Ubuntu 22.04, 64-bit). Запускается на
WebKitGTK. Linux-версию проверяли на Ubuntu 26.04: пакет ставится, программа запускается,
интерфейс, настройки, справка и отчёт о проблеме работают, русским шрифтам ничего не
мешает. Не проверено только одно — сама запись в память клавиатуры: для неё нужна
настоящая клавиатура, подключённая к Linux-машине. Поэтому релиз помечен как
экспериментальный: если что-то не работает — напишите на почту или в задачи, это ценно.

**deb-пакет** — рекомендуемый путь: он сам ставит правило udev, которое выдаёт доступ к
`/dev/hidraw*` клавиатур наших производителей тому, кто сидит за компьютером:

```bash
sudo apt install ./iohub-desktop_<версия>_amd64.deb
```

Правило ложится в `/etc/udev/rules.d/99-iohub-desktop.rules`, перечитывается при
установке; после этого клавиатуру достаточно переподключить.

**AppImage** правило поставить сам не может — файл с правилом лежит рядом с остальными
файлами релиза (`99-iohub-desktop.rules`):

```bash
chmod +x iohub-desktop-<версия>.AppImage && ./iohub-desktop-<версия>.AppImage
```

```bash
sudo cp 99-iohub-desktop.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo udevadm trigger --subsystem-match=hidraw
```

Если и после этого клавиатура не открывается, помогут права напрямую на время проверки:
`sudo setfacl -m u:$USER:rw /dev/hidraw*` (до следующего переподключения). Правило из
файла использует `TAG+="uaccess"`, то есть выдаёт доступ тому, кто сейчас сидит за
компьютером; в системе без systemd-logind можно заменить его на `MODE="0666"` — это
откроет устройства всем, поэтому только как крайний вариант. На Ubuntu с рабочим столом
доступ к `hidraw` активному пользователю обычно выдает сам дистрибутив — наше правило
нужно там, где этого нет.

Две шероховатости, о которых лучше знать заранее. В менеджере пакетов версия показывается
как `0.8.5`, даже если файл называется `iohub-desktop_0.8.5.1.2_amd64.deb`: Tauri умеет
класть в метаданные только три части номера. Полная версия — в имени файла, в заголовке
окна, внизу настроек и в справке. AppImage на Ubuntu 26.04 запустился «из коробки»:
нужен `libfuse3`, а он в системе есть. Если FUSE в системе нет вовсе, запускайте так:
`./iohub-desktop-<версия>.AppImage --appimage-extract-and-run`.

Собрать самому: `cargo tauri build --bundles deb,appimage` из папки `desktop`.
Библиотечку hidapi crate собирает сам, но нужны `libudev-dev` и `pkg-config` — полный
список пакетов в `.github/workflows/release.yml`.

## Файлы настроек

Windows — `%APPDATA%\vision.io.hub.desktop\`, Linux — `~/.local/share/vision.io.hub.desktop/`.

| Файл                 | Зачем                                                        |
|----------------------|--------------------------------------------------------------|
| `hid-allow.json`     | какие устройства программе можно открывать, вида `"05ac:024f"` |
| `iohub-desktop.log`  | журнал работы (без него отчёт о проблеме пустой)              |
| `reports\`           | сохранённые отчёты о проблемах                                |
| `firmware.url`       | одна строка `https://…` — список прошивок для «Обслуживания»   |
| `debug.on`           | подробный режим: трассировка пакетов и снимки экрана           |
| `autotask.txt`       | сценарий самодиагностики интерфейса (для разбора поломок)      |

Файл прошивок работает только по `https://` и только если вы создали его сами.
По умолчанию его нет, и программа живёт полностью без сети.

## Если клавиатура не видна

1. Проверьте кабель и порт — пробуйте без хабов и удлинителей.
2. Посмотрите в `hid-allow.json`: должна быть строка с парой вашего устройства,
   например `"05ac:024f"`.
3. Закройте другие программы, которые могут держать клавиатуру (родной конфигуратор,
   аналогичные утилиты).
4. На Linux — права на `hidraw` и правило udev выше; переподключите клавиатуру после
   `udevadm control --reload`.
5. Создайте файл `debug.on`, перезапустите программу и посмотрите последние строки
   `iohub-desktop.log` — там видно, какие устройства нашлись и почему отказ.

## Отчёт о проблеме

Кнопка **«Сообщить об ошибке»** в меню открывает панель с описанием проблемы и уже
собранным отчётом. У отчёта есть номер вида `HUB-20261119-2CA14D0F` — его же программа
ставит в тему письма и в заголовок задачи, так что случай не потеряется. Внутри:
версия программы и версия интерфейса, система, язык и экран, подключённые устройства,
последние 200 строк журнала и короткий список того, что вы нажимали перед обращением
(последние 60 нажатий, только подписи кнопок со страницы). Оттуда можно:

- **Письмо на iohub@aspidov.ru** — откроется почтовая программа с текстом и выжимкой;
- **Задача на GitHub** — откроется страница новой задачи с тем же содержимым;
- **Сохранить в файл** — отчёт ляжет в подпапку `reports`, его можно приложить.

Из отчёта вырезается имя пользователя из путей, серийный номер сокращён до последних
трёх знаков. Список нажатий берёт только подписи кнопок на экране — введённый вами
текст, раскладка и настройки клавиатуры в него не попадают. Отчёт никуда не уходит
сам: программа открывает письмо или страницу задачи, а отправляете вы их сами.
Прочитайте текст перед отправкой — он ваш. Подробно о границах: [SECURITY.md](SECURITY.md).

## Сборка из исходников

Нужны Rust (стабильный, 1.80+), Python 3 и WebView2 Runtime на Windows. Node не нужен.

```bash
python desktop/prepare_webview.py    # собирает webview/ из vendor/io-web
cd desktop
cargo tauri build                    # Windows: установщик NSIS + портативный exe
cargo tauri dev                      # разработка, с пересборкой на ходу
cargo tauri build --bundles deb,appimage   # Linux
```

Интерфейс вшивается в бинарный файл, поэтому после любой правки в `vendor/io-web/`
или `webview/webhid-shim.js` нужно снова запустить `prepare_webview.py` и пересобрать.
`cargo tauri build` ругается «Access is denied», если программа сейчас запущена.

### Как обновить дамп интерфейса

`vendor/io-web/` — это сохранённая страница web.io.vision. Производитель обновляет
конфигуратор, и догнать его можно одной командой (нужен интернет):

```powershell
# 1. скачивает свежую сборку с сайта в дамп (страница берётся прямо с сервера)
.\desktop\tools\fetch-site.ps1 -FromServer
# 2. правит номер релиза в файле VERSION на версию скачанного интерфейса
# 3. пересобирает интерфейс и программу
python desktop/prepare_webview.py
cd desktop ; cargo tauri build
```

Скрипт берёт с сервера страницу, главный модуль и стили, вычищает ссылки на чужой
домен и обходит весь JavaScript и CSS, докачивая то, чего нет на диске, — так в дамп
попадают и модули поздней загрузки (макросы, отчёты, интерфейсы экранов). В конце он
печатает список того, чего на сервере не нашлось: картинки `.art.js`, схемы `.svg` и
описания `.kle.json` в открытом доступе нет, это норма. Отдельно стоит проверить
нескачанные `.js`, `.css` и `.woff2` — их скрипт перечисляет особо.

Можно и по-старому, сохранением страницы браузером (Ctrl+S, «Страница полностью»):
получатся «IO Hub.html» и папка «IO Hub_files» рядом с репозиторием — они в
`.gitignore`, и скрипт соберёт дамп из них, если запускать его без `-FromServer`.
Так стоит сделать, если хочется сравнить: что видит браузер, то и программа.

Имена файлов у сборки меняются каждый релиз, но править в скрипте больше нечего:
модули поздней загрузки находятся обходом ссылок. Если изменился сам дамп — проверьте
якорь правок в `desktop/prepare_webview.py` и загляните в
`desktop/tools/find_firmware_urls.py`: он ищет адрес списка прошивок в свежем дампе.
Скрипт ничего не удаляет: в `vendor/io-web` останутся модули от прошлой сборки
производителя, поэтому перед обновлением папку вывода лучше очистить. А вот
`prepare_webview.py` из `webview/` лишнее убирает сам.

Проверить дамп глазами можно без сборки: `python -m http.server` в папке `webview/`
(шим там уже лежачий) либо `cargo tauri dev`.

## Номер версии

Релизы программы носят тот же номер, что у интерфейса производителя: дамп 0.8.5.1 —
и релиз 0.8.5.1. Так сразу видно, какой версией конфигуратора вы пользуетесь, и не
нужно вести вторую нумерацию. Единственный источник номера — файл [`VERSION`](VERSION)
в корне; из него же программа берёт версию для окна, справки, отчёта о проблеме и имён
файлов релиза.

Cargo и Tauri понимают только три части номера, поэтому в `desktop/Cargo.toml` и
`desktop/tauri.conf.json` стоит укороченное `0.8.5`, а полная версия приходит из
`VERSION` через `desktop/build.rs`. `prepare_webview.py` следит, чтобы дамп и `VERSION`
не разъехались: при расхождении сборка останавливается.

Одно следование этого ограничения видно в Windows: если открыть свойства файла
программы, там будет `0.8.5.0`. Имя файла, тег релиза и всё, что показывает сама
программа — в заголовке окна, внизу настроек, в справке и в отчёте, — носят полный
номер из `VERSION`.

Если нам нужно выправить что-то своё, не дожидаясь нового релиза производителя,
добавляется пятая часть: `0.8.5.1.2`. Новый релиз производителя — новый номер в
`VERSION`, счётчик наших правок при этом обнуляется.


Краткая справка, которую программа показывает в окне по кнопке «Справка», живёт в
[`docs/app-help.html`](docs/app-help.html); `prepare_webview.py` кладёт её в
`webview/help.html`. Языковых разделов два — русский и английский, выбирается по
переключателю языка в интерфейсе.

Готовые сборки собираются по тегу `vX.Y.Z` в [`.github/workflows/release.yml`](.github/workflows/release.yml):
Windows (установщик и портативная версия) и Linux (deb, AppImage, помечены как
экспериментальные) — и выкладываются в Releases.

## Чего программа не делает

- Не пишет в память клавиатуры без вашей явной команды: отправка раскладки происходит
  только когда вы сами нажимаете применение настройки в интерфейсе.
- Не обновляет прошивку по своей воле и не ищет её в сети.
- Не отправляет никуда статистику, идентификаторы устройства или содержимое раскладок.
- Не правит реестр и системные настройки, кроме собственной папки данных.
- Не меняет код конфигуратора: интерфейс остаётся тем же, что и в веб-версии.

Отдельно предупреждаем: пункт **«Default assignment»** в редакторе — это заводские
значения из каталога, а не ваши прежние настройки. Сначала сохраните свою раскладку.

## Лицензия и происхождение интерфейса

### Кому принадлежит интерфейс

Оригинальный разработчик и правообладатель конфигуратора — **IO Red Square**
(знак «IO by Red Square», сайт [web.io.vision](https://web.io.vision)). Сам
интерфейс сделан командой **White Core**: программа пишет об этом в окне
«О приложении» — «Powered by WhiteCore.» — и перечисляет авторов в
благодарностях:

* Никита Дергачёв
* Кирилл Андреев
* Максим Рощупкин
* Дмитрий Ивлев

Эти имена и этот текст берутся из самого интерфейса, мы их не добавляли и не
изменяем. Наша часть — только офлайн-оболочка вокруг него: хост на Rust, мост
WebHID, скрипты сборки и документация.

### Лицензии

Собственный код этой программы — под лицензией [MIT](LICENSE) (см. также
[CHANGELOG.md](CHANGELOG.md) и [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)).

Дамп веб-интерфейса в `vendor/io-web/` собственным кодом не является: он опубликован
здесь, чтобы программу можно было собрать, и распространяется на иных условиях —
это описано в [NOTICE](NOTICE) и [vendor/NOTICE.md](vendor/NOTICE.md). По просьбе
правообладателя дамп будет удалён из репозитория, а сборка — переведена на
самостоятельное сохранение страницы.
